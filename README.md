## Ответы на вопросы

### Чем отличается CI от CD?

**CI (Continuous Integration)** — непрерывная интеграция: каждый push автоматически собирается и тестируется. Это позволяет рано находить ошибки в коде.

**CD (Continuous Delivery / Deployment)** — непрерывная доставка или развёртывание: код всегда готов к деплою (Delivery) или автоматически публикуется после успешных тестов (Deployment).

### Что произойдёт, если тесты завершатся ошибкой на этапе CI?

Пайплайн остановится на шаге тестов. Задача `deploy` не запустится, потому что у неё есть зависимость `needs: ci` — она выполняется только после успешного завершения CI. Это защищает продакшен от попадания неработоспособного кода.

### Для чего используется директива `needs: ci` в задаче развёртывания?

Она указывает, что задача `deploy` зависит от `ci` и запускается только после её успешного завершения. Если `ci` упадёт, `deploy` не выполнится.

### Что такое артефакт и для чего он передаётся между задачами?

Артефакт — это файлы, которые сохраняются после выполнения задачи (например, собранный сайт в папке `dist/`). Передача артефакта между задачами позволяет разделить сборку и деплой: задача `ci` собирает проект и сохраняет артефакт, а задача `deploy` скачивает его и публикует. Это удобно, потому что задачи выполняются на разных runner'ах — без артефакта файлы из одной задачи не были бы видны в другой.

### Почему развёртывание не запускается на Pull Request?

В задаче `deploy` стоит условие `if: github.ref == 'refs/heads/main'`. Pull Request идёт из другой ветки (например, `feature/x`), поэтому условие не выполняется. Это сделано специально: проверять код до слияния можно и нужно, но деплоить непроверенные изменения в продакшен — нельзя.
